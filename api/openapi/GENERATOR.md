# OpenAPI TypeScript client generation

`api/openapi/openapi.json` remains the authoritative OpenAPI 3.1 contract. The generated
client in `web/src/api/generated/` is read-only and contains no project transport, error,
runtime-validation, Store, or domain-model behavior.

## Locked toolchain

- npm wrapper: `@openapitools/openapi-generator-cli@2.40.1`
- generator: `7.24.0`, selected by `openapitools.json`
- generator: `typescript-fetch`
- runtime validator available to project-owned API boundaries: `zod@4.4.3`

The wrapper, Spectral, and their transitive dependencies are locked by
`api/openapi/package-lock.json`. Product dependencies, including Zod, are locked by
`web/package-lock.json`. Do not use a global install, floating `npx`, or `latest`.

## Commands

```bash
make openapi-install
make openapi-check
make openapi-generate
make openapi-generate-check
make openapi-generated-typecheck
```

`openapi-generate` first runs the existing contract gates, writes a temporary normalized
generator input, generates into a temporary directory, checks the reviewed warning baseline
and public-model `any`/`Set` boundary, then replaces the generated directory. The normalized input
is never an alternative contract and is not committed.

`openapi-generate-check` performs the same generation and compares every generated byte with
the committed directory. It fails for missing, stale, hand-edited, or contract-drifted files.
The wrapper also removes generator-emitted trailing spaces from text output before the drift
comparison, so generated files satisfy the repository's `git diff --check` gate deterministically.

## Audited normalizer boundary

`generator-input-manifest.json` registers every compatibility projection:

- primitive `const` becomes an equivalent typed single-value enum;
- `uniqueItems` remains authoritative in OpenAPI but is removed from the temporary generator input;
  `typescript-fetch` otherwise emits `Set`, which cannot be serialized as a JSON array;
- the listed open JSON objects and unconstrained schemas use a recursive generated-only
  `JSONValue` model;
- `WorkflowTopicOutlineSection` is projected into two named, fully typed union branches;
- OpenAPI `Null` maps to TypeScript `null`; the one-line version-bound template override keeps
  that branch in generated nullable union aliases.

New open objects, unconstrained schemas, unsupported const values, boolean schemas, or changed
named-union shapes fail closed. Any new transformation category requires an explicit manifest,
normalizer, warning-baseline, generated-output, and documentation change.

## Upgrade and rollback

Upgrade the wrapper and generator together in a dedicated change. Retrieve the new upstream
templates with `openapi-generator-cli author template -g typescript-fetch`, reapply only the
strict TypeScript and nullable-union compatibility edits documented in the repository templates,
and review both template diffs against both generator versions. Update the exact package lock,
`openapitools.json`, manifest versions, warning baseline, this document, and regenerated output.

Run the commands above twice and require a clean second drift check plus generated strict
typecheck. If generation or browser/API parity regresses, roll back the wrapper, generator
selection, template, normalizer manifest, and generated directory as one versioned unit.
