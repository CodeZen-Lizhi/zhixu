## 边界

## 数据流

1. 笔记保存或导入，创建待分析任务。
2. AI 读取标题和正文，产出短简介、标签、主题层级及证据引用。
3. 系统将结果写入可追溯的知识记录，并与现有锚点计算相关性。
4. 相关性结果形成待确认的锚点关联候选。
5. 用户接受关联后，系统对锚点生成融合候选，展示新增、修改、重复和冲突。
6. 正文有实质变化时，用户发布候选，形成新的不可变汇总版本并更新当前发布指针；纯来源补充单独记录。
7. 上游正式发布后，检查依赖其内容的主笔记，对实际受影响部分生成候选和提醒。下游审核发布后才可以继续触发后续影响检查。
8. 主笔记中心读取当前发布版本；用户展开任一片段时，沿主笔记片段 → 知识点 → 来源文件 → 来源文件版本 → 原文片段返回证据。

## 关键约束

- AI 产出不能绕过现有知识声明、来源溯源和版本完整性约束。
- 当前发布版本不可静默覆盖；候选和发布必须可幂等重试。
- 跨主笔记引用记录所用上游版本及对应片段；上游新版本发布不隐式切换下游历史引用。候选须绑定上游发布版本、下游基线和引用关系，重复事件去重；基线变更重新校验，循环引用不能导致重复候选无限传播，无实际内容影响时终止传播。
- 共享来源、主题相关和实际正文引用分别表达；只有实际依赖受到影响才提出正文更新。正式发布与候选生成事件分开处理，未审核草稿不能作为已成立的新知识继续传播。
- 来源删除/失效只更新影响提示和待复核状态，不自动改正文、删除结论或改写历史版本。保留已有来源版本快照，区分原文件不可用、来源失效与结论被证伪；历史快照与当前有效性分别展示。
- 来源失效观察通过主笔记专属引用绑定记录；普通来源发现和失效恢复已按精确来源版本核验。通用Topic/Claim/Relation Impact不能替代主笔记片段依赖；证据见 discovery-failure-implementation.md 和 remaining-acceptance.md。
- 局部更新应保留未受影响章节原文；涉及人工内容的修改以可审阅差异表达。发布时核对草稿基线与当前正文，基线过期则重新合并和审阅，不用旧草稿覆盖用户后续编辑。
- 生成结果绑定冻结的 `BaseRevisionID`，最终发布另行核对当前文件、正式版本、根授权与审批。候选后的文件变化进入重新合并和审阅；不能以生成时的绑定替代写回时的基线校验。真实链路证据见 candidate-remerge-browser-verification.md。
- 冲突发布与冲突裁决分开表达。正文发布可保留未裁决冲突，但必须保留所有受证据支持的不同观点、各方来源及已知条件，阅读投影不得丢失未裁决标记；未知条件不能生成事实性补全。
- `SynthesisConflictContent` 表达多个观点，`SynthesisStatement` 保存来源与适用条件；未裁决状态贯穿候选、审核发布和历史读取，不能在渲染或重新打开时丢失。相关固定Provider证据见 remaining-acceptance.md；真实模型能否保留语义仍须外部验收。
- 纯补充来源记录与正文版本分开追踪，不修改历史正文版本的引用快照；相同来源版本重复处理不重复追加。只有正文实质变化才进入新正文版本发布流程。
- `ApplySynthesisDelta` 已分别返回正文 `Changed` 与 `SourcesChanged`；纯来源补充不能推进正文或发布版本。人工改写后须通过当前全文来源复核，再记录补源结果；旧结论支持不能冒充当前正文支持。
- 标签相同只提供检索信号，不直接决定锚点归属。
- 主笔记版本保存不可变的片段级引用快照；来源后续版本、删除或失效只产生影响标记，不改写历史主笔记的引用关系。
- AI 主题判断需保存解释依据和来源片段，便于审阅。
- 范围调整建议与来源关联候选分别表达。范围调整未经用户确认不得生效，普通来源关联确认不得隐式扩大范围；范围调整通过后重新评估相关来源，正文更新仍需融合候选发布审批。

## 来源可用性复核提醒

00108 保存主笔记/来源版本/原因的不可变复核观察，按已有精确 synthesis_revision_source 引用定位受影响片段。Worker 启动及周期执行有界幂等对账；无模型调用，在模型排空期间仍可运行。读取所选 revision 时，仅返回该版本实际使用的引用和条目，历史正文、引用绑定及发布指针不变。原因区分 SOURCE_REMOVED 与 SOURCE_QUARANTINED；恢复后仍保留历史观察，并单独读取当前是否可用，不能把来源不可用等同于结论错误。

复用核验：Health 的 MISSING_SOURCE 仅检查正式 Claim/Relation 缺证据，不能充当主笔记原文件删除信号。目前 core.source.removed_at 的删除生产者是 Git capture；普通目录扫描漏掉文件不会设置 tombstone，原文件物理缺失的自动检测、短暂删除后恢复在对账前的持久捕获、缺失 Artifact 的真实原因及历史字节打开仍待补齐。该观察表不替代上述尚未具备的事实来源，也未实现用户复核完成动作。

## 已保存历史原文的读取

SynthesisSourceView 用可选 snapshot_text 表达通过原始 Artifact hash、精确 Span 和 excerpt hash 核验的历史片段；availability 和 text 保持原有当前来源语义。原文件删除或存在新来源版本时，可以读取原不可变副本并展示历史标记；隔离来源、缺失/篡改副本不返回字节。生成路径继续要求当前来源，不能将历史 snapshot_text 送入融合。主笔记正文和后补证据使用相同只读 owner 边界。

普通本地缺失检测下一步应按已注册的精确本地路径、有界分页和有效 RootGrant 做 presence probe，不能将 ScanWorkspace 的过滤/跳过/失败等同于删除。现有 Scanner.Scan 排除 .git/.knowledge/tmp/.tmp，遇到非支持格式不会返回；os.OpenRoot 的既有安全边界可复用。持久写入必须重新核验 source/latest-version，避免并发恢复或新版本被旧缺席观察误标。

### 普通本地来源的缺失观察

Worker 复用现有周期调度，对当前授权工作区中的已登记本地 Source 做每批最多 100 条的 keyset 检查。游标也越过仍存在的文件；重启可从头检查，重复缺失不会重复写 tombstone。Workspace owner 在 Source 行锁内确认最新版本仍来自该相对路径，再调用只检查文件元数据的 filesystem port。登记与缺失观察共用 Source upsert/行锁，已完成的重新登记不会被先前页面快照覆盖。来源恢复仍通过正常扫描/登记清除 tombstone，不通过发现同名文件就宣告旧版本恢复。

只把有效根目录下明确的不存在作为删除事实。排除 Quick Capture、URL、绝对路径、内部目录；遇到权限错误、符号链接或根目录身份变化返回失败。managed runtime 在读取前及写入前复核原 RootGrant；filesystem port 还检查打开根目录与当前路径对应同一物理目录。文件系统修改不与数据库原子提交；轮询间隙的短暂删除、尚未重新扫描的恢复仍不保证被捕获，不能宣称具备文件系统事件日志。

删除后继续运行既有来源影响对账；它不修改主笔记正文或发布指针。检索查询本身已有 `source_record.removed_at IS NULL` 筛选，旧检索快照不会重新引入已删除 Source。

## 本地文件回到历史内容的版本语义

连续观察到相同当前内容时保持同一 SourceVersion；内容经历 A→B→A 时，最后一次 A 是新的不可变来源版本，复用 A 的 ContentArtifact，但不改写原 A/B 的时间戳、画像或历史引用。记录 observation_predecessor_id 绑定发生回退之前的当前版本；在 Source 锁内核对前驱和观察时间，拒绝迟到的旧观察。观察时间按数据库微秒精度比较，避免随机 UUID 决定同时间点版本的先后。

普通命令和指定 Git Commit 的重复注册仍按 source/hash 返回 canonical 版本，不因为历史命令重放而生成新的当前观察。仅实际文件扫描显式标记 CurrentObservation；canonical 唯一索引和再现观察的唯一前驱索引分别保护两类幂等。所有历史来源版本保持不可变；画像、目录和正文来源 owner 继续按最新捕获记录选择当前版本，无需将历史引用悄悄改指向新版本。


## 主笔记发布事实与后续正文依赖

主笔记发布传播必须读取完整的 Authoring 发布历史，不能轮询 Document 的当前发布指针来代替发布事件。两次扫描之间可以有多次已完成发布；前一次 ArticleRevision 被标记为 SUPERSEDED 后，其 publication binding 和精确 ProposalCommit 仍是有效历史事实。

00115 通过只读 synthesis_proven_publication 投影核对 SynthesisRevision、generated ArticleRevision、历史 PUBLISHED binding 和 ProposalCommit 的身份、projection/content hash、目标及 Git commit。Worker 在已有周期内有界补录到 workflow.outbox_event，以不可变 revision 身份生成唯一发布键；事件只含身份/hash，不含正文或路径。数据库验证事件必须对应真实已发布记录，事件正文不可修改，只有消费确认时间允许单向写入。重启、并发扫描与重复投递不应生成重复事件。该投影不是新的发布 owner，也不赋予下游写回权限。

发布事实只是正文依赖传播的前置条件。后续仍须单独保存下游片段到上游已发布 revision/item 的真实引用或包含关系，并在冻结生成输入时核对；共享原始来源不能自动推断为这种关系。传播消费者应读取事件指向的不可变版本，检查实际受影响片段及相关语义，保留无关内容和人工编辑，生成经过独立语义校验的局部候选，审核后才发布。00115 尚未实现此引用绑定或消费生成，不据此宣称跨主笔记传播完成。

历史发布补录覆盖已切换为 inactive 或已移除的工作区；工作区是否当前活动不改变曾经发布的事实。是否允许之后的本地资料读取、模型执行和候选写入，仍由对应消费者的当前工作区与授权门禁决定，记录事件本身不绕过这些门禁。


## 显式纳入已发布主笔记片段（00116）

主笔记间的正文包含关系由 v4 生成协议的 INCLUDE_ITEM 明确表达，模型使用服务端提供的笔记/片段标签；服务端复制完整事实、冲突或缺口条目，包括适用条件、缺口已有结论和原始来源。新条目保存 body_reference：工作区、上游笔记、不可变修订、真实 publication binding、片段与 projection hash。直接引用记录指向一层上游，进一步追溯通过上游自身的历史版本继续展开，不丢弃原始来源。

只有 owner 核验为当前已发布的候选修订才提供纳入能力；草稿候选不冒用旧版发布身份。冻结后的已发布修订之后即使被 supersede，仍可核验其历史发布证据。冻结和应用事务都复核发布身份，数据库从修订条目自动投影不可变 synthesis_revision_body_reference，拒绝无真实发布证明或内容不完整的新引用。父版本已有引用可伴随局部补充来源/缺口结论保留，不能回写历史关系。

BodyReference 是条目去重身份的一部分：普通同文条目与显式包含关系不能互相吞并，同一精确上游身份继续去重。v1/v2/v3 输入与请求哈希保持兼容；v4 使用 GENERATE v2 schema，独立语义审查保持 v1 schema，审查完整复制内容和原始证据。前端按不可变版本、projection hash 与片段定位，提供继续查看上游主笔记和原始资料的入口。

这一层保存和展示真实正文依赖。它尚不消费 00115 发布事件，也不生成后续局部替换候选；传播去重、相互引用终止、变更片段判定与人工编辑合并仍需继续实现，不把此基础层等同于 PRD 的更新传播验收。
