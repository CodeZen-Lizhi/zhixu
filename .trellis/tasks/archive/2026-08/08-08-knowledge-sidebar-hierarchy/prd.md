# 知识侧栏分级导航优化

## Goal

把“知识”导航从遮挡正文的大型浮层，改为层级清楚、适合高频使用的三级导航，让用户能直接理解“知识 → 能力分组 → 具体页面”的关系，同时保留现有路由、Workspace 门禁和移动端导航能力。

## Confirmed Facts

- `web/src/app/AppShell.tsx:128` 当前把“知识”渲染为主链接与独立 Chevron，并通过 Radix `DropdownMenu` 在侧栏右侧一次性展示四组入口；这就是截图中的大型悬浮面板。
- `web/src/routes/route-display.ts:43` 已经以单一 registry 保存“资料 / 探索 / 组织 / 学习”分组和组内顺序，不需要新增第二份菜单配置。
- `web/src/styles.css:100` 的桌面侧栏宽度为 232px，`rail-section` 已支持纵向滚动；移动端在 920px 以下改用 Sheet。
- `web/src/app/AppShell.test.tsx:45` 与 `:154` 当前分别锁定桌面和移动端浮层菜单、Escape 焦点恢复行为，改动时必须同步替换为新层级导航的键盘与移动端契约。
- 三级导航实现后，一级“知识”、二级当前分组和三级当前页面同时使用浅蓝背景与左侧蓝线，用户认为这种选中状态层级重复、视觉不够简洁。
- 二级分组当前没有图标，而一级与三级都有图标；同时三级行的视觉起点与二级文字过于接近，用户认为层级不连贯且缩进不清楚。

## Requirements

### R1. 真实三级层级

- 一级为“知识”，二级为“资料 / 探索 / 组织 / 学习”，三级为各组具体页面。
- “资料收件箱”必须与其他具体页面一样处于第三级，不再同时充当“知识”一级链接的隐式默认目标。
- 菜单内容、顺序、图标和路由继续从 `routeDisplayRegistry` 派生，不复制导航事实。

### R2. 交互与当前状态

- 不再使用当前一次性展示全部入口的大型 Dropdown 面板。
- “知识”使用侧栏内 Disclosure 控件；展开后常驻显示四个二级分组，不使用向右级联飞出菜单。
- 四个二级分组可独立展开或收起，展开后在原位显示对应三级链接；用户可以同时展开多个分组。
- 首次渲染时“知识”保持展开；当前知识路由所属分组自动展开。展开状态只属于当前 AppShell 生命周期，不写入浏览器存储。
- 当前知识路由必须同时标识一级“知识”、所属二级分组和当前三级页面。
- 展开/收起控件使用按钮、Chevron 和正确的 `aria-expanded` / `aria-controls`；具体页面保持语义化链接和 `aria-current="page"`。
- 键盘可以依次到达每个展开控件与可见链接，焦点环清楚；隐藏分支不能残留可聚焦节点。

### R3. 视觉与响应式

- 层级主要通过缩进、字号、字重、左侧导轨和活动状态表达，不使用卡片、阴影或嵌套浮层堆叠。
- 二级分组补充与“资料 / 探索 / 组织 / 学习”语义对应的紧凑图标，与文字和 Chevron 形成稳定的三列；分组图标的尺寸与颜色权重低于一级图标。
- 三级入口必须相对二级文字再向右缩进至少一个 16px 网格单位，不得让二、三级文字或主要视觉起点看起来平齐。
- 桌面侧栏不得遮挡正文；导航高度超过可用空间时只滚动侧栏导航区域，设置入口仍保持可达。
- 移动端复用相同层级语义并放在现有主导航 Sheet 内；选择具体页面后关闭 Sheet。
- 维持项目现有白蓝冷色、44px 触达区、可见 Focus 和 Reduced Motion 约束。

### R4. 兼容边界

- 不改变任何业务 URL、Route Section、Workspace 连接门禁、API、Query 或页面数据流。
- 未连接 Workspace 时仍只显示工作台和设置，不渲染知识层级。
- 创作、工作台、设置和紧凑入口态不因本次改动改变语义。

## Acceptance Criteria

- [x] 桌面端不再出现 `[role="menu"][aria-label="知识菜单"]` 大型浮层，知识导航不覆盖正文。
- [x] 导航呈现“知识 → 四个分组 → 十个现有知识入口”的真实层级，顺序与 registry 一致。
- [x] 四个二级分组可独立展开/收起；当前路由所属分组自动展开，同时展开多个分组不会互相关闭。
- [x] `/search` 等知识子页会高亮“知识”、所属分组和当前页面；当前页面具有 `aria-current="page"`。
- [x] 展开控件的名称、`aria-expanded`、`aria-controls` 和键盘行为可被 Testing Library 验证。
- [x] 移动端 Sheet 中层级完整，点击具体入口后关闭 Sheet，Escape 关闭 Sheet 后焦点返回主导航按钮。
- [x] 未连接门禁、一级导航和现有深链回归测试通过。
- [x] `npm run typecheck --prefix web`、定向 AppShell 测试、`npm run lint --prefix web`、`npm run build --prefix web` 与 `git diff --check` 通过。
- [x] 在 1440x900、1024x768、768x1024 和 390x844 真实浏览器中无遮挡、横向溢出、文字裁切或不可达入口，Console/Network 无新增错误。
- [x] 二级分组均有稳定的图标、文字与 Chevron 列，图标不与三级页面图标争夺视觉权重。
- [x] 三级行比二级文字至少多一个 16px 网格单位的右缩进，桌面和移动 Sheet 都能一眼区分二、三级。
- [x] 当前三级页面是唯一使用浅蓝选中面与短蓝线的强选中项；一、二级只通过字重、前景色和图标表达当前路径。

## Out of Scope

- 不重做全站侧栏、品牌、Topbar、Settings 或业务页面。
- 不调整知识能力分组名称、入口数量、路由和后端能力。
- 不新增导航依赖或把路由状态写入浏览器持久化存储。

## Key Decisions

- 用户选择侧栏内树形导航，明确拒绝级联飞出和当前大型 Dropdown。
- 一级“知识”承担 Disclosure，不再作为 `/inbox` 的直接链接；“资料收件箱”成为“资料”分组内的标准三级入口。
- 分组使用彼此独立的展开状态，兼顾完整层级和快速跨组访问；当前路由只负责保证所属分组可见，不覆盖用户已展开的其他分组。
- 用户确认同时采用 A“单一焦点”选中态和完整层级优化：二级分组补充语义图标，三级相对二级再右缩进至少 16px，只有当前三级页面使用浅蓝选中面与短蓝线，一、二级只表达路径归属。
