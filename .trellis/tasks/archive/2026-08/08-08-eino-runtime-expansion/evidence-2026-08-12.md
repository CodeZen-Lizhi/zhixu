浏览器在正式 Answer 发布前观察到的连续非空 SSE chunk 事件与延迟：

| 视口 | 草稿 chunk 事件 | 首次草稿观察延迟 |
|---|---:|---:|
| Desktop 1440x900 | 2 | 44379ms |
| Mobile 390x844 | 8 | 44831ms |

正式 Answer 完成观察延迟为 101328ms。这里记录的是浏览器首次观察草稿的跨进程延迟，不冒充 Provider 首 Token 指标。两个浏览器均在正式 Answer 尚不可见时先观察到至少两个连续、非空 SSE chunk 事件，随后由正式 REST Answer 替换草稿；移动端没有重复提交问题。SSE parser 只接受严格的 `generation/sequence/content` chunk。浏览器门禁持续拒绝可见草稿和正式 Answer 包含 session 或 CSRF token，并用凭据长度与两组 32-bit 滚动指纹扫描 draft SSE 网络响应；页面不接触 HttpOnly session 原值，扫描器只保留每个凭据长度的环形字节窗口与布尔状态，正文不会写入回执或诊断日志。

host-relay 结果证明真实外部 Chat 能驱动完整 Eino 产品链路，但不冒充容器直连外部 HTTPS 网络路径已通过。外部 HTTPS Embedding 由独立 live gate 证明。

## 3. PostgreSQL / River / Fence / Replay

在一次性 PostgreSQL 18 + pgvector 实例中，以 `-race -tags=integration -p 1` 运行并通过：

- Conversation -> River -> RAG -> Feedback 正式组合；
- `ReadSource@2` Tool request/refusal/replay 与可信审计；
- Tool receipt response-loss、STARTED CAS UNKNOWN 与 secret boundary；
- draft session lease fence、generation 和有序 chunk；
- Answer Finalizer 的 PUBLISHED/ABORTED、reclaim fence、wall-clock lease、commit response-loss replay；
- Runtime Claim 的 pause/cancel、delivery checkpoint、并发 reclaim 与旧 owner fence。

RAG v2 的冻结产品序列为 `PLAN,AGENT,ANSWER,INITIAL,REVIEW`。`ReadSource@2` 使用 Eino `ReturnDirectly`，因此产品链路只有一次 AGENT ModelCall；通用多轮 ReAct 由独立 Runtime 合同覆盖。

一次性 PostgreSQL 容器已按精确名称移除，未复用或修改其他工作区数据库。

## 4. 流式错误边界

新增并通过回归：ANSWER Provider frame 即使同时携带正文和 `tool_calls`，也必须在写入任何 draft 前以 `AGENT_ANSWER_STREAM_INVALID` 失败，并将 ModelCall 归约为 FAILED。Adapter recording 边界和 AnswerStreamRuntime 均做 fail-closed 校验。

真实门禁复验还暴露出 writer 会在首个内容到达时立即排空队列，把首帧和后续帧合并成一个持久 chunk。最小回归先稳定复现 `first/second/third` 被写成单一 chunk，再修为首个 Provider frame 独立落库、后续 frame 继续有界合并；10 次 race 回归及最终指纹化网络扫描版本的真实 2/8 chunk 事件闭环通过。浏览器在业务终态先于第二个 chunk 事件到达时会立即失败，不再等待完整超时。
