# 工作台首页重设计

## Goal

把 `/dashboard` 从“系统状态与能力清单”改造成知序的产品首页：用户第一次进入时先理解这是自己的本地知识工作台，并能立即继续真实工作，而不是先阅读 API、数据库、RAG 和请求 ID。

首页必须同时建立产品辨识度、下一步行动和真实业务上下文；不得用静态样例或虚构统计换取视觉丰满。

## Confirmed Facts

- 未连接 Workspace 时，`web/src/features/business/DashboardPage.tsx:19` 在连接入口后直接渲染完整 `SystemStatusPage`，因此系统诊断成为首页主体。
- 已连接 Workspace 时，Dashboard 已有真实的 Proposal、Source Version、Workflow 和 Workspace 查询，但同时展示完整系统状态、Operational Coverage 与能力说明，技术事实压过用户任务。
- `web/src/app/AppShell.tsx:187` 在 `/dashboard` 固定显示“今日编辑台”，未区分首次进入、未连接和已连接场景。
- 产品定位是单用户、本地优先、Markdown 与 Git 为事实源、AI 受控执行的知识工作台，不是通用笔记编辑器或运维控制台，见 `docs/product/PRD.md:150-165`。
- 另一个任务 `.trellis/tasks/07-31-workbench-navigation-visual-redesign/` 已收敛为 Clearline 全局白蓝主题，并在独立 worktree `/Users/zhenglizhi/GolandProjects/zhixu-workbench-navigation-visual-redesign` 完成尚未提交的实现；首页必须基于该 worktree 继续，不得从暖色旧壳另起一套样式。
- Source Version 列表只公开路径、捕获时间和处理状态，不公开正文摘要或内容访问历史；因此效果稿中的“最近进入”必须落实为“最近捕获的资料”，不得伪造最近查看、最近编辑或摘要。
- Proposal 和 Workflow 列表分别按更新时间倒序，服务端没有跨资源 Priority 字段；“先处理这一件”只能是有测试锁定的首页展示策略，不能描述成服务端排程结论。

## Requirements

### R1. 首页职责

- 首页负责回答三个问题：这是哪里、我现在处于什么工作上下文、下一步最值得做什么。
- 首页不得常驻展示完整服务能力矩阵、请求 ID、版本、开发认证模式或“未交付能力”说明。
- 系统状态只在故障会阻断当前动作时出现为一条可操作的异常提示，并提供进入设置或重试的入口。

### R2. 未连接 Workspace 的入口态

- 第一视口必须以“知序”作为主品牌信号，并用一句具体文案说明本地知识、连接与受控 AI 的价值。
- 第一视口提供唯一主操作“连接知识目录”，直接进入现有 Workspace 配置流程；次级入口不得与主操作争抢视觉权重。
- 页面采用“沉浸式知识地图入口”：知识关系画布铺满主内容区，品牌与连接操作位于画布留白区，不再使用左文案、右插图的常规分栏 Hero。
- 未连接时没有真实业务数据，画布只用 `本地资料 → 知识主题 → 证据关系 → 待审提案` 表达品牌化知识脉络；不得伪装成用户已有节点或统计。
- 入口图只承担品牌表达，不承担完整数据模型说明：只保留四个中文节点、一条蓝色主路径和最多一条极淡补充关系。
- 不显示聚类外圈、次级节点、关系动词、英文节点类型、图例、均匀网格或矩形节点卡片。

### R3. 已连接 Workspace 的工作态

- 复用真实 Workspace、Proposal、Source Version 和 Workflow 数据，把需要处理的异常、待审内容和最近资料放在首页前部。
- “先处理这一件”只显示一项明确动作，并按“等待人工的 Workflow、失败 Workflow、待审 Proposal”的首页展示规则选择；同类内使用服务端更新时间，Proposal 可在当前有界结果中按风险等级排序。界面不得声称这是后端全局优先级。
- 资料区只能展示最近捕获的 Source Version 及其真实路径、时间、安全、解析和索引状态；不得显示访问历史、正文摘要、主题归并或与 Proposal/Workflow 的猜测关联。
- 空数据时提供可执行的起步路径，例如扫描资料、进入检索或打开知识图谱；不得填充示例数字。
- 存在 Active Workspace 时，每次启动直接进入带品牌表达的工作态；不显示独立欢迎封面，也不增加“进入工作台”确认步骤。
- 工作态采用“安静的今日知识桌面”：首屏先给出一项明确的下一步，再承接最近捕获的资料；知识脉络作为工作上下文，不作为装饰背景。

### R4. 视觉方向

- 首页必须具有网站级首屏构图和产品辨识度，但仍是可立即操作的应用页面，不做纯营销落地页。
- 采用概念 B 的严格无衬线白蓝体系：冷白画布、深墨文字、克制蓝色主操作、细线网格与真实知识脉络；不再保留入口标题的装饰性中文衬线。
- 工作态通过连续工作面、分隔线和信息密度建立秩序；入口态通过全画布关系图建立冲击力。两者不得只更换标题、字体或颜色。
- 设计必须与全局导航视觉规划收敛为一套 Token，而不是在 Dashboard 内建立孤立主题。

### R5. 交互与响应式

- 桌面首屏采用非对称构图，主操作和核心产品视觉均在第一视口内，并露出下一段内容线索。
- 移动端在 `390x844` 下品牌、标题、主操作和产品视觉不重叠；主操作无需滚动即可发现。
- 保留可见焦点、键盘操作、非纯颜色状态和 `prefers-reduced-motion` 降级。

## Acceptance Criteria

- [ ] 未连接 Workspace 时，第一视口不再出现完整系统状态、能力矩阵、请求 ID或版本信息。
- [ ] 第一视口清晰显示“知序”、产品价值和“连接知识目录”主操作，并通过真实产品语义的视觉建立辨识度。
- [ ] 未连接 Workspace 时，关系画布明确表现产品对象模型，不冒充真实用户数据。
- [ ] 知识图能在桌面和移动首屏中完整读出 `本地资料 → 知识主题 → 证据关系 → 待审提案` 的主脉络，节点标签无遮挡，且不依赖图例解释。
- [ ] 已连接 Workspace 时，首页以“安静的今日知识桌面”优先显示真实待办、异常和最近资料；空态提供真实可执行路径且不伪造数据。
- [ ] 首页不出现“最近进入”、虚构摘要、总量数字或猜测的跨资源关系；最近资料明确表示按捕获时间排序。
- [ ] 系统正常时不占用首页内容区；阻断性异常以紧凑、可操作提示出现。
- [ ] Dashboard 与全局导航共用同一视觉系统，在 `1440x900` 与 `390x844` 下无横向溢出、遮挡或主操作掉出首屏。

## Out of Scope

- 不修改后端 API、数据库、Workspace 创建或扫描语义。
- 不新增内容访问历史、Source 正文摘要、跨资源优先级或 Dashboard 聚合接口。
- 不重做 Graph、Review、Collection、Artifact 等业务页内部交互。
- 不把公开营销网站、登录页或启动动画作为独立产品交付。
