# 稳定主笔记、独立范围审批与可追溯演进

零散笔记可在不同语境中包含相同知识，用户需要集中维护汇总内容并追溯其来源。采用稳定主笔记身份及经确认的锚点范围：正文有实质变化时形成不可变候选版本，经用户发布后更新当前发布指针；完全重复的知识仅追加补充来源，保留历史版本当时的引用快照。该决策来自已批准的[知识锚点需求](../../../.trellis/tasks/09-12-knowledge-anchor-synthesis/prd.md)，文档状态表示决策已接受，不表示全部实现已验收。

AI 根据标题、内容和已有知识归纳范围与来源建议，用户无需逐篇填写元数据。来源关联审批和范围调整审批分别表达：接受来源不隐式扩大范围，接受范围不直接发布正文；范围变化后按新范围重新评估相关知识。这样保留用户对持续维护方向的控制，同时避免新增一段 MySQL 知识就无意将 Redis 专项扩展为数据库全集。

未采用直接覆盖当前正文，因为它无法保护人工内容、审核边界和历史证据；未采用每次整理创建另一份独立笔记，因为它使阅读入口与后续维护目标分裂。稳定身份需要额外维护发布指针、来源账本和候选基线，但允许集中阅读与严格的历史追溯并存。

多个主笔记可共享来源。共享来源、主题相关、内容包含和实际正文依赖分别表达；上游正式发布只对实际受到影响的正文依赖生成下游候选，下游仍需审核发布，重复事件和循环引用不得无限传播。来源失效保留正文和已保存的历史快照，持久记录实际失效原因与复核提示，不把缺失来源自动判为错误结论。
