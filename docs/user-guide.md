# 知序完整用户指南

## 1. 产品概览

知序把本地 Markdown、文本、PDF、网页和附件组织成可检索、可追溯、可审批的个人知识库。它适合技术知识积累、写作整理、复习和面试准备，也适合希望数据保留在自己 Workspace 与 Git 中的用户。

产品闭环是：选择 Workspace → 记录或导入资料 → 解析与检索 → 整理、创作或问答 → 审阅 Proposal → 安全写回与 Git 留痕 → 用图谱、健康、时间线、复习和面试持续维护知识。

所有正式知识变更都遵循“先建议、后审批、再写回”。AI 可以分析、生成候选和解释证据，但不能绕过用户审批直接改文件或创建 Git Commit。

> **阅读边界**：本文描述完整产品范围和目标使用方式，不维护版本交付清单。文中的“当前支持”或“当前模式”只说明对应能力的使用限制，不能据此推断整个产品已经交付；实际完成状态与验收证据只在 [Trellis 任务](../.trellis/tasks/) 维护，未交付方向见 [开发路线图](roadmap.md)。

## 2. 开始使用（需求 10.1）

### 2.1 激活 Workspace

- **用途**：把已有本地目录注册为稳定知识空间，并只向当前目录授予精确访问。
- **入口**：首次执行 `./zhixu up --workspace <absolute-root>`；目录尚无 Git 且明确同意初始化时增加 `--initialize-git`。后续使用 `./zhixu up` 或 `./zhixu restart`。
- **主要操作**：检查目录与 Git，等待 Web、API、Worker 和 PostgreSQL ready，然后访问默认地址 `http://127.0.0.1:8080`；修改 `ZHIXU_HTTP_PORT` 后使用对应端口。
- **结果**：服务端返回唯一 Active Workspace；历史、索引、问答和页面缓存均按稳定 Workspace ID 隔离。
- **限制**：浏览器不能选择或挂载宿主机目录；`ZHIXU_WORKSPACE_ROOT` 已废弃。Git、数据库或精确挂载校验失败时不会激活半完成状态。

### 2.2 切换 Workspace

- **入口**：`./zhixu workspace switch <absolute-root> [--initialize-git]`。
- **主要操作**：本机命令依次校验目标、停止旧 Workspace 新写入、撤销旧 grant、准备并验证新 grant。
- **结果**：切到 B 后只显示 B 的数据；切回 A 会恢复 A 原有 ID、索引和历史。
- **限制**：切换期间页面会短暂重连。失败会恢复上次成功选择；无法安全恢复时保持不可用，不混合两个 Workspace。父目录与子目录的物理包含关系不会因 Workspace ID 隔离而消失。

### 2.3 Dashboard 与状态通知（需求 10.19、10.21）

- **用途**：从一个入口了解当前 Workspace、优先待办、最近捕获、健康趋势、复习安排和需要人工处理的任务。
- **入口**：连接后的 Dashboard，以及 Workflow、Proposal、索引、Health Scan 和 Review 等业务页面的状态通知。
- **主要操作**：先处理页面顶部的数据库、Git、索引落后或人工恢复告警，再进入等待中的 Human Task、待审批 Proposal、失败任务或最近活动详情。
- **结果**：用户能从摘要回到权威对象继续审批、重试或恢复；刷新页面后由服务端重新查询完整状态。
- **限制**：通知只表示相关事实可能变化，不是任务结果本身；严重错误不能被统计卡片遮盖，通知也不得携带 Secret、完整正文或敏感路径。

## 3. 记录、导入与解析

### 3.1 Inbox 与 Quick Capture（需求 10.2）

- **用途**：快速保存文字、链接、文件和图片，或批量导入 Markdown、TXT、PDF 与网页正文。
- **入口**：全局 Quick Capture、Inbox 拖拽/文件选择、Inbox 目录发现、URL 输入或粘贴文本。
- **主要操作**：命名资料、选择处理方式、查看安全检查、解析、分块、Embedding 和索引进度；失败后按可重试提示继续。
- **结果**：原始 Capture、Source、Source Version 和已有字节的 Content Artifact 保持不可变；重复内容按 Hash 复用，不重复进入默认检索。
- **限制**：不支持的类型在进入工作流前被拒绝；可疑、解析失败或不完整内容进入隔离，不能进入默认索引。候选 Profile 只提供带 Source Span 的整理线索，不是正式 Claim。

### 3.2 内容解析、标准化与分块（需求 10.3）

- **用途**：把不同来源转换为可定位、可重建的统一文本片段。
- **入口**：资料通过安全检查后自动执行；索引维护时也可重建。
- **主要操作**：查看 Markdown/TXT 结构、PDF 页、网页段落、标题层级、代码块和 Source Span；对 OCR_REQUIRED 或解析失败资料人工处理后重试。
- **结果**：Chunk 保留来源版本和精确定位，可从搜索、回答和证据回到原始资料。
- **限制**：扫描 PDF 的 OCR 为 Should；重建不能改变 Source Version，Chunk 策略变化会创建新索引版本。

## 4. 搜索与问答

### 4.1 索引与混合检索（需求 10.4）

- **用途**：按关键词、语义、过滤条件和关系找到知识与原始资料。
- **入口**：搜索页、各工作台的材料选择器、图谱/集合/问答中的查找动作。
- **主要操作**：选择 Workspace 范围、Topic、来源、时间、内容状态和 Keyword/Hybrid/Semantic 模式，打开 Evidence 定位。
- **结果**：全文与向量候选经过融合、去重和可选 Rerank；结果显示请求模式、实际模式、索引版本和降级原因。
- **限制**：默认只检索最新批准正式版本；Draft、历史版本、隔离资料和已归档内容需显式范围。Embedding 不可用时 Keyword 仍可用，Hybrid 明确降级，Semantic 不返回伪成功或伪空结果。

### 4.2 RAG 问答（需求 10.10）

- **用途**：基于本地批准知识回答问题，并展示可打开引用、冲突和推断边界。
- **入口**：问答页或知识对象的“询问”动作。
- **主要操作**：输入问题与范围，处理系统提出的 Clarification，阅读分阶段进度、Answer、Citation、冲突提示和拒答原因，并提交反馈。
- **结果**：只有通过证据资格、引用定位与忠实度校验的回答才会发布；多轮对话保留问题、回答和反馈记录。
- **限制**：当前对话是固定 retrieval-first 的单节点 RAG，不是开放 Tool Loop；进度为阶段事件而非逐 Token 事实源。证据不足会拒答，Provider/数据库故障显示错误而不是伪装成拒答。

## 5. 创作、整理与正式入库

### 5.1 文章优化与版本管理（需求 10.5）

- **用途**：对选中文章进行轻度润色、结构整理或基于证据的深度优化，同时保护事实、代码、引用和用户禁改范围。
- **入口**：文档详情、创作工作台或资料处理动作。
- **主要操作**：选择模式和约束，审阅逐项 Diff、理由与来源；接受、拒绝或手工编辑 Change Item。
- **结果**：形成新的不可变 Article Revision Draft；批准后通过统一 Proposal 发布，旧正式版本仍可追溯。
- **限制**：无来源内容不得伪装为事实；审批期间目标变化会进入三方比较，不能覆盖用户当前文件。

### 5.2 主动创作与文件历史

- **用途**：从空白 Working Draft 写作，冻结版本，查看当前路径历史，并在不重写历史的前提下恢复旧内容。
- **入口**：创作工作台、新建文档、文档历史页。
- **主要操作**：自动保存 Working Draft，显式 Freeze 为不可变 Revision，安全预览；按路径查看 managed、external 和 current change，比较任意版本并创建 restore Proposal。
- **结果**：发布使用 CREATE_ONLY 或受控恢复 Proposal；恢复生成新的反向内容 Commit 和追加 Revision。
- **限制**：Working Draft 不是正式知识；stale Revision、dirty target、HEAD/path/blob 漂移均阻止写回。恢复不执行 reset、checkout 或历史重写。

### 5.3 知识抽取与关系分析（需求 10.6）

- **用途**：从资料中识别 Topic、Claim、适用条件、证据与候选关系。
- **入口**：摄取完成后的整理流程、材料整理工作台或显式关系分析。
- **主要操作**：审阅 NEW、COMPLEMENTARY、DUPLICATE、CONFLICT、LOW_CONFIDENCE 判断及其来源、适用条件和置信因素。
- **结果**：生成正式知识、补充、合并、关系或 Conflict Proposal；低置信结果继续检索或等待人工。
- **限制**：向量相似不是正式关系；模型置信度不是用户确认；不同适用条件不能自动判定为冲突或重复。

### 5.4 Proposal 与人工审批（需求 10.7、10.8）

- **用途**：集中审查任何可能改变正式知识、关系、文件或 Git 的建议。
- **入口**：审批中心、工作流 Human Task、文档/图谱/健康/冲突详情。
- **主要操作**：按类型、风险和状态筛选；检查目标、证据、引用、Diff、影响和回滚计划；批准、驳回、暂缓或创建修订。批量审批为 Should，且只能用于同质低风险项。
- **结果**：Approval 固定绑定 Proposal Revision、Change Hash、目标版本和批准时 Git 基线；驳回原因成为反馈。
- **限制**：登录或高权限 Token 不等于写授权。审批后目标或 Git HEAD 变化会进入 NEEDS_REVISION；模型不能生成或扩大写授权。

### 5.5 安全写回、Git 与回滚（需求 10.9）

- **用途**：把已批准变更以可恢复方式写入 Workspace，并创建可反查 Proposal 的 Commit。
- **入口**：批准后的持久 Workflow 自动执行；恢复和回滚仍通过受控 Proposal。
- **主要操作**：查看版本校验、临时写入、原子替换、Diff、Commit、增量索引和回归验证；失败时按 checkpoint 重试或人工恢复。
- **结果**：文件、Commit、Revision 映射、索引和审计相互关联；外部结果不明确时保留现场。
- **限制**：不执行 `reset --hard`、`checkout` 或任意 push；索引失败不伪装为整体完成。Git/文件/数据库无法证明一致时进入只读恢复。

## 6. 知识产物与导出

### 6.1 Artifact 与材料整理（需求 10.11）

- **用途**：从资料和正式知识生成专题文章、总结报告、合并结果、面试复习文档等可版本化产物。
- **入口**：Artifact 工作台或整理工作台。
- **主要操作**：自然语言描述目标，增删并确认 Suggested Material，选择专题文章/合并/总结/面试复习模板，冻结 Input Snapshot，审批大纲或 Human Task，按章节检查 Citation、Coverage 和 GAP。
- **结果**：得到可恢复的 Artifact Revision；可继续编辑、导出 Markdown，或创建发布 Proposal。
- **限制**：材料、Evidence 和 Template Revision 在 Snapshot 后不可被后续 owner 变化改写；证据不足必须显示 GAP。Artifact 不因生成成功自动成为正式知识。

### 6.2 数据导出（需求 10.22 / AC-33）

- **入口**：Collection 详情和 Workspace 设置。
- **主要操作**：导出 Collection Markdown、领域 Metadata JSON 或 Workspace 附件 ZIP，查看状态、过期时间、Hash/大小并受控下载。
- **结果**：导出文件是有权限、可恢复、可审计的 Export Job 结果。
- **限制**：当前支持 `MARKDOWN`、`METADATA_JSON` 和附件 ZIP；`EVALUATION_JSON`、`AUDIT_JSON`、CSV/XLSX、字段映射与公式字段不属于当前能力。导出结果不是新的知识事实源。

## 7. 探索与维护知识

### 7.1 可操作知识图谱（需求 10.12）

- **用途**：从 Topic、Claim 和已确认 Relation 查看全局、局部与路径关系。
- **入口**：图谱页、Topic/Claim 详情。
- **主要操作**：过滤关系/来源/状态，按需展开邻居，打开节点、关系和 Evidence 抽屉，保存当前会话布局或转到完整列表。
- **结果**：图谱展示 PostgreSQL 中可追溯的只读投影，并连接版本、健康问题和时间线。
- **限制**：服务端和画布均有界；大结果必须用分页列表。候选关系不进入正式 Graph Canvas，布局不是领域事实。

### 7.2 语义反向链接（需求 10.13）

- **用途**：发现尚未确认但可能相关的知识。
- **入口**：图谱候选面板、Topic 扫描或知识对象详情。
- **主要操作**：查看 Candidate 的证据、置信因素和 Fingerprint，确认、忽略或重新评估。
- **结果**：忽略记录可防止无意义重复；确认只创建 typed Relation Proposal，批准后才写入正式 Relation。
- **限制**：Candidate 是独立候选事实，不是正式 Relation，也不应混入图谱查询结果。

### 7.3 智能集合与动态视图（需求 10.14）

- **用途**：用条件组合形成不复制知识的动态集合。
- **入口**：集合页或知识筛选结果的“保存为集合”。
- **主要操作**：组合 Topic、来源、状态、时间、健康和文本条件；使用列表、表格或卡片视图；执行受控批量动作或导出。
- **结果**：集合保存查询定义，打开时从当前权威数据重算。
- **限制**：表格只是 Web 视图，不是电子表格导入/公式系统；批量正式变更仍生成 Proposal。

### 7.4 知识健康中心（需求 10.15）

- **用途**：持续发现孤立、重复、冲突、过期、来源缺失和索引异常。
- **入口**：健康中心、变更后的局部扫描或维护设置。
- **主要操作**：按类型、严重度和状态查看 Evidence；忽略并记录原因、重新扫描或创建修复 Proposal。
- **结果**：稳定 Fingerprint 去重问题，证据变化可重新打开，趋势可追踪。
- **限制**：扫描与修复是两步；Health Issue 不能直接修改正式知识。

### 7.5 时间线与影响分析（需求 10.16）

- **用途**：追踪 Revision、Proposal、Approval、Commit、Conflict、Artifact、Review 等知识演进，并分析变更下游影响。
- **入口**：时间线页、知识对象详情或变更详情。
- **主要操作**：过滤事件、比较版本、生成影响报告，查看受影响对象并创建 `downstream_update` Proposal。
- **结果**：事件与 owner 可相互反查；影响报告固定输入版本。
- **限制**：批准影响建议不代表下游已经自动执行；时间点快照为 Should。

### 7.6 Conflict 调查与解决（需求 10.24）

- **用途**：把互相冲突的 Claim 作为长期对象调查，而不是用新文章静默覆盖。
- **入口**：Conflict 页面、关系分析/RAG/健康结果或手动标记。
- **主要操作**：并排查看 Claim、来源、适用条件、证据和影响；追加本地或受控网页调查；选择当前有效、接受条件差异、综合替代或继续暂缓。
- **结果**：解决 Proposal 保留调查历史，并触发图谱、RAG 样本、Review Card、Artifact 和健康的影响分析。
- **限制**：证据不足保持 OPEN/DEFERRED；`ACCEPTED_DIVERGENCE` 用于不同条件下都成立的结论。

### 7.7 知识对象生命周期（需求 10.23）

- **用途**：统一管理 Document、Topic 和 Claim 的新建、重命名、移动、拆分、合并、归档、替代和删除。
- **入口**：知识对象详情、创作或管理动作。
- **主要操作**：预览链接与反向引用影响，选择主对象和目标目录，审阅文件与关系 Diff 后提交 Proposal。
- **结果**：合并保留全部来源；归档内容退出默认 RAG；删除保留审计和 Git 恢复路径。
- **限制**：生命周期变更都经 Proposal。Topic 删除不能连带删除 Document/Claim；物理删除是高风险操作，先展示完整影响。

## 8. 学习、复习与记忆

### 8.1 记忆与反馈学习（需求 10.17）

- **用途**：保存用户确认的偏好、纠正、目标和有限情景信息，以改进后续体验。
- **入口**：Memory 页面、回答反馈或 Interview 产生的候选。
- **主要操作**：确认 Candidate、编辑、暂停、恢复、删除或查看来源与到期信息。
- **结果**：只有确认内容进入长期 Memory；来源与 provenance 只读可追溯。
- **限制**：模型推断不能直接成为长期记忆；用户命令不能伪造 provenance。删除长期记忆需要二次确认。

### 8.2 智能复习、闪卡与面试（需求 10.18）

- **用途**：从 Topic、Collection 或岗位目标生成带引用的问题，评估掌握度并形成学习路径。
- **入口**：Review、Review Session、Interviews 或知识对象的复习动作。
- **主要操作**：创建 Deck、审批 Card、开始会话、提交文本回答并查看评分、缺漏、来源和调度；面试可选择岗位、难度、时长并连续追问。
- **结果**：评分绑定不可变题目快照与 Scorer 版本；FSRS 更新幂等；知识缺口可生成 Review-origin 或 Interview-origin Learning Path。
- **限制**：答题前不展示答案或证据正文；文本回答是 Must，语音是 Could。过期或失效题目必须刷新，不能由客户端重签。

## 9. 工作流、工具与运行状态

### 9.1 工作流中心（需求 10.19）

- **用途**：查看超过数秒的持久任务，处理 Human Task，并安全暂停、恢复、重试或取消。
- **入口**：工作流列表、详情和各业务页面的任务链接。
- **主要操作**：查看节点、Attempt、等待原因、进度、错误和补偿；按允许的状态发起 pause/resume/cancel/retry。
- **结果**：离开页面不影响执行；重进后从服务端恢复；崩溃后从 lease、幂等记录和 checkpoint 继续。
- **限制**：取消不会抹去已经发生的副作用；副作用结果未知时进入人工恢复，不能盲重试或假 Completed。

### 9.2 Tool Calling 与权限（需求 10.20）

- **用途**：让受控工作流调用搜索、读取、引用校验、Git 状态等最小工具，并在独立的 Workspace 分析模式中完成有依赖的多步只读任务。
- **入口**：对话中的 Workspace 分析模式，或各业务工作台启动的受控任务；工具不是普通用户的任意命令入口。
- **主要操作**：提交一次复合目标，查看 Agent 依次读取 Git 状态、检索知识、打开 Source 和校验 Citation；任务时间线区分 Token 增量、工具请求/结果、等待和最终回答。需要写入时只审阅其生成的 Proposal。
- **结果**：每次调用按服务端冻结的 Schema、Capability、Workflow allowlist、超时、幂等和审计执行；后一步可以使用前一步的受控结果，刷新后从持久事实恢复。
- **限制**：受限 Agent 与固定 RAG 是独立模式，并受步骤、时间、并发、Token 和费用硬预算约束。Prompt、网页和 Source 都是不可信数据，不能指定 Workspace、Credential、路径、命令、Git 参数或扩大权限；模型不能直接调用写工具、修改文件或创建 Commit。

### 9.3 可观测性、审计与成本（需求 10.21）

- **用途**：解释任务发生了什么、为何失败、用了哪些模型/版本以及消耗多少。
- **入口**：Workflow/Proposal/Commit/Document 详情和系统状态。
- **主要操作**：查看节点、Model Call、Retrieval、Tool、Human Task、Commit、Token、耗时、受控错误和 Trace 关联；按对象与时间查询审计。
- **结果**：任意批准写入可从 Commit 反查 Proposal、Approval 和 Workflow；技术详情使用稳定错误码。
- **限制**：日志、Metric、Trace、Audit 和浏览器不得包含 API Key、Cookie、完整正文、绝对路径或完整 DSN；未配置价格时只显示 Token，不伪造成本。

## 10. 设置与维护（需求 10.22）

- **用途**：管理当前 Workspace 的模型、Embedding、Rerank、Git Remote、索引、工作流重试、记忆和数据保留。
- **入口**：设置页；宿主机 Root 切换仍使用本机命令。
- **主要操作**：测试模型连接、查看 desired/active 配置；配置单 HTTPS Remote 与只写 Token；手动同步、查看 Git/索引分列状态；增量或全量重建索引；清理过期临时数据。
- **结果**：设置变更可审计，Secret 只写不可回读；模型不可用时相关能力明确 unavailable/degraded，不影响文件浏览和关键词检索。
- **限制**：配置测试不得修改正式知识；自动 Git 同步默认关闭且远端失败不回滚本地写回。清理不删除 Source Version、Git Commit 或批准知识。

## 11. 典型端到端路径

### 首次连接 Workspace 并进入工作台

1. 确认目标目录已经存在，并按需要准备 Git。
2. 用本机命令激活目录，等待 Root、Git、数据库、挂载、端口和服务检查完成。
3. 打开命令输出的本地地址，在 Dashboard 确认 Active Workspace 和系统状态。
4. 需要切换时使用本机命令；切换后先确认新 Workspace，再继续导入、检索或审批。

### 建立一条可信知识

1. 用 Quick Capture 或 Inbox 保存资料。
2. 等待安全检查、解析、分块与基础索引。
3. 在整理工作台确认材料与 Evidence，或运行关系分析。
4. 审阅知识/关系 Proposal，必要时修改或驳回。
5. 批准后等待 Safe Writeback、Git Commit、Reindex 和回归验证。
6. 从搜索、图谱、时间线和 Commit 反查来源与变更链。

### 搜索或提问并核对证据

1. 选择 Workspace、Topic、来源和时间范围，再选择关键词、混合、语义搜索或 RAG 问答。
2. 查看实际检索模式、降级、Clarification、冲突和拒答原因。
3. 打开每条 Evidence/Citation，核对原始资料位置与结论支持关系。
4. 提交回答反馈；证据不足时补充资料或调整范围，不把无引用回答直接当作正式知识。

### 从多份资料形成产物

1. 在 Artifact/整理工作台描述主题与目标。
2. 增删候选材料并显式确认冻结 Snapshot。
3. 审批大纲或分类 Human Task。
4. 检查每章 Citation、Coverage、Conflict 与 GAP。
5. 导出 Markdown，或创建发布 Proposal 后进入统一写回。

### 用知识准备面试

1. 从 Topic、Collection 或已有 Artifact 创建 Review Deck/Interview。
2. 审批题目或直接开始服务端生成的会话。
3. 提交回答，查看引用、评分、遗漏和追问。
4. 将暴露的缺口加入 Learning Path，回到原始来源复习。
5. 对可靠的偏好或纠正确认 Memory；不确认的推断不会长期保存。

### 发现并处理知识冲突

1. 从关系分析、RAG 或健康中心打开 Conflict。
2. 对比双方 Claim、适用条件、时间和 Evidence。
3. 添加本地或受控网页调查并保留每次记录。
4. 选择当前有效、接受条件差异、综合新 Claim 或暂缓。
5. 审批解决 Proposal，再检查图谱、回答、复习与 Artifact 的影响建议。

### 从图谱、健康或时间线形成修复建议

1. 从图谱、健康中心或时间线打开关系、孤立项、过期项、来源缺失或下游影响。
2. 核对对象、版本、Evidence 和问题 Fingerprint，必要时重新扫描或生成影响报告。
3. 选择忽略并记录原因，或创建关系、内容、生命周期或 `downstream_update` Proposal。
4. 审批后回到原对象确认结果；Approval 不代表所有下游更新已经完成。

### 失败、刷新与外部修改后的恢复

1. 页面刷新、重新登录或进程重启后，先从任务、Proposal 或对象详情重新读取服务端状态，不依据旧通知或浏览器缓存猜测结果。
2. 普通可重试失败沿原 Run、Job 或幂等身份继续；不要重复创建可能已经发生副作用的命令。
3. 文件、Git HEAD 或目标版本变化时查看三方差异，修订 Proposal 或重新确认目标，不能覆盖外部修改。
4. Git、文件与数据库无法证明一致时停止正式写入，进入只读恢复并保留临时文件、Commit、索引和审计证据。
5. 按 [运行与恢复手册](operations.md) 检查进程、Workflow、索引与一致性状态；只有权威状态重新闭合后才恢复写入。

运行、备份与故障恢复命令见 [运行与恢复手册](operations.md)；产品必须满足的字段级验收见 [产品需求与验收](requirements.md)。
