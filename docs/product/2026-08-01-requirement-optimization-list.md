# 2026-08-01 需求优化清单

## TODO 1. 取消首页的一次性凭证门禁

- [x] 状态：已完成（2026-08-02）

### 用户诉求

- 用户应当可以随时直接打开 `/dashboard`，不需要重新运行启动器或获取一次性链接。
- 关闭页面后重新进入、关闭浏览器后重新进入、换用其他浏览器时，首页都应正常打开。
- Controller 重启后，首页不应因为旧会话失效而显示“控制链接已失效”。
- 首页访问不应与某一个浏览器首次消费的一次性凭证绑定。

### 当前问题

- 当前一次性 `#control=...` 凭证只能交换一次，并只为消费它的浏览器建立控制 Cookie。
- 控制 Cookie 当前有效期为 12 小时；换浏览器、Cookie 被清除、会话过期或 Controller 重启后，需要重新生成并打开一次性链接。
- 首页和高权限 Host Controller 共用同一会话门禁，导致只想查看首页的用户也被控制凭证拦截。

### 常见产品做法

- 普通桌面笔记应用通常依赖操作系统用户权限，打开应用即可进入首页，不额外要求一次性链接。
- 仅在本机运行的 Web 笔记应用通常允许直接访问 `localhost`，或者使用可以长期恢复的普通登录状态。
- 局域网、云端或多人使用的笔记应用通常采用账号密码、验证码或 SSO，而不是每次启动都变化的一次性链接。
- 删除数据、开放本机目录、安装插件、修改服务配置等高权限操作，可以单独要求确认、重新登录或本机授权。

### 产品判断

- 一次性控制凭证用于保护 Host Controller 的高权限操作，其安全目的成立。
- 使用同一凭证阻止普通首页、笔记和知识内容浏览，不符合常见笔记产品的使用体验。
- 安全限制应放在高权限操作入口，而不是整个应用的首页入口。

### 目标体验

- 任意本机浏览器访问 `http://127.0.0.1:8080/dashboard` 都能直接进入首页。
- 首页及基础只读内容不再显示一次性控制链接失效页面。
- 多浏览器、重新打开和 Controller 重启不影响首页可访问性。

### 安全边界

- 本需求取消的是首页的一次性凭证门禁，不等于默认开放所有本机控制能力。
- Workspace Root 授权、工作区切换或移除、Docker 运行时重建、敏感设置修改等高权限操作仍需独立保护。
- 后续方案应拆分“始终可访问的首页”与“需要授权的 Host Controller 操作”，避免恶意网页、浏览器扩展或本机其他进程直接触发宿主机操作。

### 验收标准

- 新浏览器或无 Cookie 浏览器直接访问 `/dashboard`，首页正常展示。
- 同一浏览器关闭后重新打开 `/dashboard`，首页正常展示。
- 使用多个浏览器同时访问 `/dashboard`，均可正常展示首页。
- Controller 重启后直接访问 `/dashboard`，首页正常展示。
- 未经授权的客户端仍不能执行 Workspace Root、运行时或其他高权限控制操作。

### 实施结果

- 首页和普通业务路由改由独立业务认证与公开运行时状态决定，不再依赖一次性 Controller 凭证。
- 业务认证关闭时可直接进入工作台；业务认证开启时进入普通登录页，不显示控制链接失效页。
- `/`、`/workspace`、目录授权、Workspace 切换或移除、Docker 重建等控制能力继续要求有效控制会话。
- Controller 暂时不可达时，页面会卸载旧工作区内容并自动重试；恢复后回到原业务路由。
- 已通过双浏览器、桌面/移动、Controller 重启、launcher restart、HTTP 权限边界和自动化回归验收。
